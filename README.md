##  UI/UX設計

### 情報の優先度と「引き算」のUI
自己紹介や展望など、伝えたい文章量が多くなったため、読んでくださる方が情報過多で疲弊しないよう以下の設計を行いました。
- **4つのセクション分割**: 「自己紹介」「制作物紹介」「技術スタック」「展望」に分離し、興味のある情報から主体的にアクセスできるように選択肢を提供。
- **モーダルによる情報の階層化**: すべての文章を一度に表示せず、重要度の低い補足情報はモーダルウィンドウ内で記述。情報の認知負荷を軽減しています。（Visionセクションの -継続的な自主学習について-）
- **装飾の最小限化**: 各セクションのカードスタイルを統一し、アニメーションや過度な装飾を抑制。「どこを見ればいいか」迷わないよう、視線誘導に配慮したシンプルな設計としました。
- **レスポンシブ対応**: PCだけでなく、スマートフォンからも閲覧可能です。

##  技術的挑戦と制作から得た学び

### 課題：複数HTML管理から「JSによる動的制御」への挑戦
以前の制作物（美顔器のLP）ではページごとにHTMLを用意していましたが、コードの重複や管理コストが課題でした。今回は **「JavaScriptで表示内容を制御する仕組み」** を実装するため、「`index.html` と `portfolio.html` の2枚のみ」で画面を切り替えるサイトの構築に挑戦しました。

### 直面した問題と、モダンフロントエンドの必要性の理解
この動的制御の実装により、 **「ブラウザの戻るボタンを押すと、意図した画面に戻らず前のページに離脱してしまう」** という画面遷移（履歴管理）の問題に直面しました。

この課題を解決するアプローチを調べる中で、**History API**の存在を知り、これまで意識できていなかったブラウザの履歴の仕組みや、設計段階で「目的に応じて、サイトを構築する方法を精査することの重要性」について学ぶきっかけとなりました。

現在Reactを学習中ですが、今回のポートフォリオサイトではあえて複数の技術を詰め込まず、Vanilla JSで実装したことでサイトの品質を一定に保ちつつ、なぜ現代の開発でReactなどのライブラリが広く使われているのか、その存在意義を身をもって理解することができました。

##  AI（Claude）との協働プロセス

### 1. 差分検証の徹底
- **VS Codeによる差分比較**: コードが生成されるたびに、VS Codeのクリップボードとファイルを比較する機能を使い、**既存ファイルとの差分を1行ずつ検証する習慣**を身につけました。
- **バグの未然防止**: AIが指示とは異なる部分を変更していたり、既存コードを消去しているケースを検知し、変更の意図を確認した上で**必要最小限のコードだけを自身の手で選別**して差し替えました。サイト全体への影響範囲を確認しながら、小さなまとまりごとにコードを書き換えていくことで、不要なバグの混入を防ぎました。


### 2. UI/UXを意識した細やかな修正
- **クロスプラットフォーム対応のフォントスタック調整**:
  AIが出力した初期コードは極端にフォントサイズが小さく、フォントスタックが漏れていたため、読みづらい上にOSや端末ごとに表示がバラつくリスクがありました。そこで、複数環境での視認性を担保するために**フォントスタックを明示的に再設計**。さらに、PCの画面上だけでなく、**スマートフォン実機での検証**を通して、最適なフォントサイズへと微調整を重ねました。
- **デザインの統一**:
  セクションごとにレイアウトがバラバラに出力される課題に対し、まずは一つのセクションで **「見本となるカードレイアウト」を検証ツール上で細かく調整して完成** させました。その後、AIに対して「この完成したレイアウトをベースに、他のセクションも同様の規則で修正するように」と、サイト全体の統一感を意識した明確なディレクションを行いました。

## 今後の展望

### 1. Reactへのアップデート
今回Vanilla JSでの実装を通して、実際の開発現場ではコンポーネントの再利用性や開発効率の観点からReactなどのライブラリが主流であることを再認識しました。今後はより **「効率的かつ安全で、実務に即した実践的なWEBサイト・アプリケーション構築」** ができるようReactを始めとしたモダンな開発技術の習得を進めていきます。

### 2. Webシステム全体の仕組みの探求
今回、「ブラウザの仕様や仕組み」の理解不足から不具合を経験したことで、フロントエンド領域の学習だけでは意識しづらかった、**Webの裏側の仕組みへの関心**が生まれました。
フロントエンドエンジニアとして「最適な技術や実装手段」を選択するためには、画面の見た目だけでなく、Webシステム全体の構造・仕組みの知識が必要不可欠だと実感したため、今後もフロントエンドの枠にとらわれず、必要だと感じた情報は積極的に調べ、**Web全体の総合的な知識を持つエンジニア**になれるよう努めます。
